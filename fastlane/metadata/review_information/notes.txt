Responses to the App Review information request, numbered as in your message:

1. SCREEN RECORDING — A recording captured on a physical iPhone, starting from app launch and covering onboarding, the permission prompts (Local Network, Photos), adding a share, sending photos and files, sharing via the share sheet extension, and importing files back, is attached to our reply in App Store Connect. The app has no account registration or login, no purchases or subscriptions, and no user-generated content shared between users, so those flows do not exist.

2. DEVICES TESTED — Tested via TestFlight on a physical iPhone 16 Pro running iOS 26.6, against a real SMB server: Samba on Linux.

3. WHAT THE APP DOES — SMBDrop moves photos, videos, and files between an iPhone and the user's own SMB network shares (a NAS, a Windows/macOS shared folder, or a Samba server), and imports files from those shares back to the phone. It is completely free: no account, no cloud service, no subscription, no ads. Target audience: home and small-office users who own a NAS or file server and want to offload camera photos or fetch files without a cloud intermediary. Transfers go directly from the phone to the user's server over the local network.

4. SETUP AND ACCESS — The app has no user accounts, so there is no demo login; the sign-in fields below are intentionally blank. To test with any Mac: System Settings → General → Sharing → enable File Sharing, and under its ⓘ options enable "Share files and folders using SMB" for a user account. In SMBDrop: Settings → add a share → enter the Mac's IP address and that user's username and password → tap "Find Shares" and pick a listed share → "Test Connection" → save. You can then send photos/videos from the Photos tab, send documents from the Files tab, share into the app from the Photos share sheet, and browse the share and download files back from the Import tab. Any Windows shared folder, Samba server, or NAS works the same way. No sample files are needed — any photo or document on the device can be sent.

5. EXTERNAL SERVICES — None are used for core functionality. All SMB transfers run on-device using the open-source AMSMB2 library, talking directly to the user's own server; no data passes through any server of ours. The only network call outside the user's LAN is the optional Settings → "Request a Feature" form, which posts the user's typed message to our Cloudflare Worker relay and is emailed to us via Resend. No authentication services, payment processors, data providers, analytics, or AI services are used.

6. REGIONAL DIFFERENCES — None. The app functions identically in all regions.

7. REGULATED INDUSTRY / THIRD-PARTY MATERIAL — Not applicable. The app operates in no regulated industry and contains no protected third-party material. The AMSMB2 SMB library is used under its open-source (MIT) licence and is credited in Settings → About → third-party notices.

PERMISSIONS — The app requests Local Network access (required to reach the SMB server) and Photos access (to pick items to send; add-only access to save imported media). Credentials are stored only in the device Keychain. No data is collected.
